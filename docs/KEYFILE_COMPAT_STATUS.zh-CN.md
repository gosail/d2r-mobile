# 游戏原生角色 .key 与三端键鼠：实现边界（PR #2）

更新：2026-11-06。原始游戏生成的角色文件为唯一正常运行时来源，保留游戏自己的保存机制。此页记录**已提交的源码与测试**，不是实际游戏/硬件验收报告。

## 存档归属与事务

- 游戏通过原有 `nn::fs` 接口操作 `<角色>/<角色>.key`、`.ctl`。HLE 将存档挂载到 `save.work`，游戏 `Commit` 时才原子替换正式 `save`。
- `dm_pc_profile.c` 选择角色时**不创建、不拷贝、不覆盖缺失的 `.key`**。仅从正在运行的原生事务工作目录读取已有的 `.key`；没有挂载时可读取正式存档快照。游戏自己的新建角色流程和默认键位不受宿主干预。
- 只读检查和实际键值查询都重新读取工作目录，能看到游戏重新写出的文件和新一次 Commit 后的目录内容；切角色立即清除旧内存状态。
- 用户在控制页修改键位时，只修改游戏已生成的同一份 `.key`，按原格式对应记录的两个 VK 字节写入。原生文件修订采用原 inode 内的 `pwrite`、`fsync` 和首次修改时的 `.bak` 备份；保留其它字节、inode、模式位以及游戏文件系统的原始扩展属性。由原有 `save.work` → `Commit` 流程负责持久化；没有第二套正式存档。
- 原先移动版自定义的 HID→模拟手柄配置仅在 `<角色>.kbm`，也写当前 `save.work`；旧版文本 `.key` 只读迁移到 `.kbm`。原生 `.ctl` 从未由键鼠编辑器写入。
- 游戏原生文件缺失、未知头或非法布局时，控制页提示不可编辑，**不会替游戏合成新的默认 `.key`**。菜单或尚未生成文件的阶段，物理键盘通过现有手柄桥提供导航回退；有合法游戏文件后切到原生动作表。鼠标中键/滚轮同理，未知格式不执行猜测映射。

## 已验证的文件结构

本项目仅取得一份角色级样本，长度 1142 字节：两字节头 `25 00`，其后 114 条十字节记录（57 组主副键）。每条按小端 `uint32 cmdId / uint16 vk / uint32 slot` 解释；观察到槽位 1/0。支持所有通过成对校验的记录、保留未知命令 ID 与未编辑值、拒绝有歧义的文件。用户的角色配置**未写入仓库或用作默认键位**。

原版经典 D2 `default.key` 的六字节头与角色级二字节头不同。当前解析器只接受已确认的角色级 `0x0025` 变体；不可宣称涵盖全部 D2R/Switch 版本。

代码位置：`dm/host/dm_keyfile.{h,c}`、`dm/host/dm_pc_profile.{h,c}`、`dm/host/hle_fs.c`。

## 三个平台

- **iPadOS**：`UIPress.key.keyCode` → USB HID → Windows 虚拟键值 → 游戏角色 `.key` 命令 ID；设置里可选主键／副键、捕获物理键、解除绑定，亦可绑定鼠标中键 `0x100` / 滚轮 `0x103,0x104`。
- **macOS**：`NSEvent.keyCode` 转 USB HID，走同一命令映射；原生控件保留鼠标、滚轮与物理按键捕获；支持以上 `.key` 编辑。
- **Android**：`KeyEvent` → USB HID → JNI 原生 `.key` 解析／保存；支持主副键、鼠标中键／滚轮选择，键盘捕获时拦截游戏输入。
- 三端共享游戏侧的 `dm_pc_input.c` 运行时派发，保留原鼠标悬停、左键拾起/放置、右键使用和手柄独立通道；物理鼠标左/中/右的三种逻辑角色仍可在 `.kbm` 中配置。
- 已接通的原生键盘命令通过角色文件查询，不在原绑定键位上保留硬编码快捷键；八个已知技能槽使用项目现有 B/X/Y/R 和 ZL 翻页桥，避免猜测额外技能槽对应的手柄按钮。

## 尚未完成及风险

1. **D2R PC 全部动作等价**尚未实现。原版 PC 16 个技能快捷槽不能简单等同于 Switch 控制器的 8/12 槽。当前可靠动作覆盖部分技能、药剂、地图、常用面板、武器切换与滚轮技能选择；其余 ID 可保存但可能尚不能执行。需要核实原版 guest 函数后逐个接入。
2. **游戏覆盖写**：虽然每次读取都与游戏文件同步，游戏自己在设置页持有旧键位且后来重写文件时，可能覆盖宿主修改；是否存在这条路径需真实游戏验证。当前不会用宿主预提交副本强行覆盖游戏文件。
3. **格式兼容**：未用两个不同的原生游戏自动生成样本做 A/B 测试；其它长度、版本、复合按键仍可能不受支持。
4. **输入体验**：三端真正游戏运行、iPad 外接设备、Android 键鼠/悬停、Mac UI 操作、全场景拖动物品与锁定怪物仍需真机验收。
5. **并发同步**：iCloud/导入仍按角色目录整体合并，不保证多个设备同时修改单个键位可自动合并。

## 现有验证

`dm/host/tests/t_keyfile.c` 检查解析、字段保持、备份和并发冲突；`t_pc_profile.c` 使用**合成的游戏生成文件**检查不自动创建、`save.work` 编辑／正式快照隔离、游戏重写后的重新读取、角色切换、inode/权限保持及输入派发；`t_kbmap.c` 验证无 `.key` 的键盘导航回退、游戏生成文件后切换原生动作、原生 `.ctl` 保留及旧私有格式迁移。`dm/ios/tests/` 提供三端源码合同检查，Apple 语法检查与 Android SDK 编译由 CI 执行。这些不构成 ROMFS/IPA 完整编译和实体键鼠测试。
