# 原版 .key 兼容及 PC 输入映射审计（PR #2）

> 2026-11-06 审计基线：`43c65e1740fa49764aa2387f5b7fdaee60b4d05d`；后续变更均在原 Draft PR #2 分支提交。本文是验收账本，**不代表完整 D2R PC 行为或真实设备验证**。

## 当前二进制证据及边界

用户提供的原始样本仅用于私下核对，**没有将其内容、键位或原文件提交到仓库**。

- 已实测样本长度为 1142 字节，前两字节 `25 00`，随后 114 条 10 字节记录；57 个不同的低位操作 ID，每个 ID 两条。
- 观察到：前 4 字节可能为小端操作 ID；偏移 +4 是 16 位键值（含 `FFFF` 和超过 255 的编码）；+6 的 16 位字在样本中取 1/0，分别在各 ID 的两条记录上出现。+2/+3 和 +8/+9 在此样本均为零，**意义待核实**。
- `dm_keyfile.c` **只支持观察到的头值 `0x0025` 和成对 10 字节记录变体**。该值是“受支持的头字”，并未证明是版本号、记录数、或任何官方规范常量。
- 允许同一变体内**任意合法数量的 ID 对**；不硬编码 57 或 1142，保留所有 32 位 ID、未知字段、记录顺序和键值。遇到未知头、非成对或歧义布局返回错误。
- `dm_keyfile_parse` → `dm_keyfile_data` → 再解析，完全不改动字节；`dm_keyfile_set` 只改匹配记录的键值两字节。存储使用冲突检测、`.bak`、临时文件、`fsync` 和原子改名。
- **仍缺少**第二份真实样本、原版游戏中验证头、ID、主副标志、鼠标/组合键及完整扫描码含义的实验。因此未将这个观察结果冒称“完全兼容 D2R”，也**不使用当前猜测生成所谓官方默认 .key**。

## 与项目已有输入架构的冲突

原项目在 `dm_kbmap.c` 中曾将键盘 USB HID 翻译为 Switch 手柄按键（WASD/JKUI 等）；还将私有 `D2RMobileKeyboard=1` 文本数据写到角色 `<hero>.key` 中。

该映射不等于 Windows/PC 的 Diablo II 操作表。二进制 `.key` 的原生键值也不能未经转换当成 USB HID usage。

为保护既有角色文件，此次先做了存储空间隔离：

- `<hero>/<hero>.key`：原生二进制文件；由 `dm_keyfile.{h,c}` 解析/最小编辑；当前**尚未接到运行时动作表、设置页或自动创建**。
- `<hero>/<hero>.kbm`：继续保存原有 D2R Mobile “键盘模拟手柄”映射，Mac/iPad/Android 原有功能保留；外置鼠标的三个角色映射也仍由它保存。
- 旧版私有 `<hero>.key`：只有精确匹配项目标记文本才以**只读方式**迁移到 `.kbm`；任何原版二进制 `.key` 均不作覆盖。
- 原生 `<hero>.ctl`：保留游戏自身管理，不更改原始数据布局。

## PC 官方行为依据及尚待验证细节

- Blizzard 2.3 版本说明确认鼠标快捷技能有 **16 个 PC active skill bindings**、可选 Quick Cast、手柄最多可用 **12 个直接激活技能的按键槽**。参考：<https://news.blizzard.com/en-gb/article/23746020/diablo-ii-resurrected-patch-2-3-highlights-coming-soon>
- Wowhead PC 键位表列出传统 **F1–F8**、**1–4 药剂**、**Tab 地图**、**Alt 物品标签**、**Shift 站立攻击**、**I/B 背包**等。参考：<https://www.wowhead.com/diablo-2/cn/guide/keyboard-shortcuts-pc>
- 资料和用户反馈显示不同 PC **Resurrected/Legacy** 预设的技能快捷键可能不同，不能将 F 键预设与数字键预设混入同一官方配置。除非对目标客户端版本进行实际回放/对照，否则这里不填写未经核实的完整 ID→按键默认表。
- 2012 年经典 Diablo II 控制列表并非 2026 D2R 本地键位二进制协议规范，不能把操作顺序直接当成 D2R ID 语义。参考：<https://wikiwiki.jp/diablo2r/CONFIGURE%20CONTROLS>

## 未完成前的安全门槛

1. 取至少两份不同原版角色 `.key`（同一游戏版本）、记录 UI 具体改动及前后差异，确认 ID、编码、组合键、主副标记及未知字段。
2. 对照目标 D2R 实际菜单，确定 Resurrected / Legacy 两套独立默认表，至少验证新角色载入后能在原生控制菜单正确显示。
3. 再将解析器接入实际设置页面、冲突检测、设备映射与角色切换；建立“UI 改键 → 游戏执行 → 重启仍生效”的端到端测试。
4. 三平台依次实测世界悬停、连续 tooltip、拿起后持有/装备/入仓/丢弃、长按攻击目标 ID、触摸与手柄回归。
5. 只在完整 App 编译并加载用户授权游戏资源、实际外设事件回放成功后标记对应验收。
