# 方案 A：角色原生按键文件（PR #2）

2026-11-06 更新。游戏原生 <角色名>.key 与 <角色名>.ctl 是仅有的角色级持久化控制文件。

原生 .key 由游戏生成，宿主只修改已验证记录的虚拟键字段；.ctl 仍由游戏管理。默认键位没有来自需求的额外限制，当前实现尚不自动复制任何用户模板。

运行时不读取、不写入私有 .kbm，也不会迁移 sw_keyboard.txt 或旧私有文本 .key。原生 .key 修改成功不依赖第二份配置保存成功；仍通过 save.work 和原有 Commit 事务持久化。

物理键盘 HID 转虚拟键，经当前角色 .key 查命令 ID，再将已验证的命令桥接成 Switch 手柄输入（部分技能、药剂、面板等）。在主菜单、角色未创建 .key 的情况下，使用不持久化的内置键盘→手柄导航回退。保持原生手柄输入通道独立。

例：将原生 Skill 1 命令绑定到物理键盘 X → 宿主发送 Switch A → 原生游戏使用 A 技能槽当前绑定的技能（例如火球术）。这里无须解析 .ctl：技能归属继续由游戏管理。源码层已对齐，仍需实机核对。

鼠标保持左键主交互、右键使用；中键/滚轮通过已支持的原生 .key 特殊 VK 绑定。原先私有侧车支持的左/右键任意重映射暂不再显示，避免给出实际不能持久化的设置。

已确认的 12 个技能位置与原版手柄映射为：1=A、2=B、3=Y、4=X、5=R、6=ZR；7–12=ZL+对应的六个按钮。映射依据为原版 HUD SkillButton1..6 与游戏绑定表，不凭空读取或覆盖 .ctl。第二组 ZL 须至少提前经过两次真实 GetNpadState 采样再按技能键；极短按键也补发一次两次采样宽度的技能键脉冲，失焦/切角色重置状态。

2026-11-07 增量：键鼠模式在原生技能树的真实技能图标上悬停后，按角色 .key 已指定的 Skill 1–12 快捷键，可通过原版 Y 绑定框将当前技能写入相应的原生手柄技能位；由游戏管理技能位的实际绑定。宿主不生成新 .key/.ctl 格式，绑定快捷键仅作为运行时输入桥，流程有原生弹窗确认、超时与焦点清理。此路径仍未经过真机验收。

键鼠 Shift 按原生命令 36（Stand Still）阻止鼠标按空地发起/维持地面行走，不借用 Shift 做技能第二组；第二组仍按角色已绑定的独立快捷键输入 ZL+技能键。Apple 两端移除了重复绘制的怪物血条，目标显示交由游戏原生 MonsterHealth；Android 仅在没有确认收到同一怪物的原生 MonsterHealth/SetInfo 时保留自绘兜底；收到原生目标信息时自动抑制重复血条。原生目标展示是否覆盖全部怪物尚未实机核实。

2026-11-07 后续修复：左/右物理 Cmd 保留为**运行时**第二技能组预览/组合修饰，原生游戏接收 ZL，HUD 同步展示第二组角色 .key 真实快捷键，Cmd+Skill 1–6 可激活/重绑定对应 Skill 7–12。角色 .key 格式不变；原版 Shift 命令 36 仍控制原地站立，Shift+左键怪物改走原生技能按键且不发送鼠标自动追怪命令。

PC 人物/物品/技能/任务等快捷键不再孤立地打开内容子面板，而是先通过原生 PLUS 打开完整 UISwitcher，再切对应页面。已验证原版布局包含 TouchClose，键鼠模式隐藏所有已打开窗口中的手柄提示，保留原生可点击关闭按钮和 HUD 的实际鼠标操作按钮。鼠标悬停敌对怪物会在原生游戏线程复用本版本 main+0x455a80(unit) 的 MonsterHealth/SetInfo 生成路径；不会改变触摸/手柄本来的锁怪逻辑。三端真实资源与运行时表现仍未验收。

已知限制：解析器仅支持已验证的 0x0025 二进制布局；Skill 13–16、完整 PC Quick Cast、全场景物品拖放、三平台完整编译及外接键鼠实机仍待验收。
