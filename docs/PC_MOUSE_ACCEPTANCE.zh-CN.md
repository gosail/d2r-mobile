### 不变的边界

- `<角色>.key`：原游戏自有原生二进制按键记录，控制页只修改已生成文件的指定 VK。
- `<角色>.ctl`：原游戏自有手柄键位。
- 无额外的角色级键盘配置文件；运行时将 .key 命令转换为已确认的控制器操作。
- 真实游戏未生成 `.key` 时，不用另一个人为默认表冒充原版。
- 鼠标中键 `0x100`、滚轮 `0x103` / `0x104` 可在三端原生编辑器选择；左键固定主交互、右键固定使用。
- 承认与原版 PC 在技能位、Quick Cast、物理鼠标按下语义和完整词缀上的差距，不能把静态测试通过等同于交互验收。

### 验证顺序

先对目标 Switch 游戏版本采集两名角色自然生成的 `.key`，在游戏内部修改同一动作并对比字节差异；再使用 Mac/iPadOS/Android 各自设置页修改主、副键，在游戏中运行、保存、关闭并重进，检查文件与执行动作一致性。键鼠长按/释放、角色切换、触摸与手柄回归以及鼠标物品拖放需分别录屏验证。

当前 CI 包含可移植 C 单元测试、三平台输入源码合同、Objective-C 语法检查与 Android SDK Java 编译；不含完整游戏资源、真机键鼠及全部原版行为回放。

## 2026-11-06 方案 A 调整

不再创建或使用 .kbm；仅保留原生 .key/.ctl 的角色级持久化。键盘到 Switch 手柄的转换保留在运行时，未支持的命令不猜测映射。已将 Skill 1→原版手柄 A、Skill 2–6→B/Y/X/R/ZR、Skill 7–12→ZL+对应按钮；键盘 X 可通过 .key 绑定 Skill 1 并复用手柄 A 上当前的游戏技能。ZL 先于技能键采样，且短按不漏脉冲。以上为代码和合成输入测试，真实游戏行为仍待验收。
