## 当前机制和证据

- 世界悬停：`dm/host/dm_world.c` 发布 `dm_world_hover_view`，Mac/iOS/Android 分别在出图层上方只读显示。
- 背包光标：`dm_ui_mouse_hover_now` 用原版焦点刷新，鼠标持有物品时不使用触屏的闲置收纳。
- 连续攻击：`g_mouse_lock` 以怪物 ID 和类型为锚点；不合成键鼠目标以外的手柄目标。
- 控制页：Mac/iPadOS/Android 已实现宿主层「键鼠 / 手柄」切换：键鼠编辑器可编辑 USB HID 键位及物理鼠标三键；手柄模式保留原生 `KeyBindingMenu` 与 `.ctl`。**原生 Key1/Key2 仍属于手柄的备用键位列，尚未从原生页面结构上改成两种设备来源。**
- 存档：`<角色>/<角色>.key` 保留给原生二进制文件，`<角色>/<角色>.kbm` 为本项目 HID→手柄模拟配置，`<角色>/<角色>.ctl` 保留原生手柄存储；新增二进制 codec 尚未连接到游戏动作执行路径。

## 额外验收原则

1. 每个场景在三种平台各自进行鼠标事件录屏与游戏日志比对。
2. 同时回归手指单击、长按拖动、手柄技能绑定和切换 UI 的原逻辑。
3. 无三端真实角色文件及角色切换/同步测试结果时，角色级读写不可标记通过。
4. 静态 CI 只是代码约束，缺少用户资源时无法执行完整编译或游戏帧回放。

## 键鼠配置（2026-11-06 更新后的分离方案）

**原版 .key 二进制兼容已列为必需目标，但当前尚未完成端到端接入。** 本项目原有 HID→手柄模拟配置写入 `<角色>/<角色>.kbm`（`D2RMobileKeyboard=1`），上个版本私有文本 `.key` 和 `sw_keyboard.txt` 仅作为只读迁移来源。新建的原生二进制 `.key` codec 独立保留数据；游戏原生 `.ctl` 不改动。

- **Mac 默认基线**：WASD = 左摇杆；J/K/U/I = A/B/X/Y；Q/E/Z/C = L/R/ZL/ZR；F/G = 摇杆点击；方向键 = 十字键；Space = A。移动端加 F1–F8 原生技能位、1–4 药水十字方向、M 地图。
- **iOS**：`DmMetalView pressesBegan/Ended/Cancelled` 通过 `UIKey.keyCode`（USB HID 码）交给配置层；失活清除按下状态。控制页内置分段切换「键鼠 / 手柄」，键鼠侧使用原生滚动编辑器，手柄保留游戏原版页面。
- **Android**：`KeyboardInput.java` 把 `KeyEvent` 转同一 USB HID 码，由 JNI 交给独立键盘通道；控制页内置「键鼠 / 手柄」与滚动编辑器，游戏鼠标分发对编辑器控件放行；切后台、失焦清除按下状态。
- **手柄**：继续使用原有 `KeyBindingMenu` 和 `dm_pad_set`，与 `dm_kb_set` 分离；触屏保留 `dm_input_set`。
- **自动测试**：Linux 原生 C 对照覆盖默认键位、组合按键、松键、移动、F5 技能、M 地图以及重启读盘；静态检查三端入口，Apple Objective-C 语法检查，Android 键盘 UI 类 SDK Java 语法检查。
- **待实机验证**：iPad 键盘能否稳定成为 first responder、Android 键盘系统截获、原游戏按键消费、控制页事件可见性、技能与药水实际效果、配置文件在各平台重启后是否正确载入；iOS/Android 的鼠标左、中、右键已可重映射为「主点击 / 次要使用 / 切地图」三种角色（不是无限制任意动作），还需设备事件验证；Mac 也已接入角色 `.kbm` 中 `mouse0..2` 三键角色重映射（同样仅限三种动作），尚需实机验收。

## 2026-11-06 角色文件名规则与冲突保护（已更新）

角色目录仍为 `$DM_SAVE/<角色名>/`，目前分开存储：

- **原生 PC 键鼠**：`<角色名>.key`，观察到的二进制变体由独立 `dm_keyfile` 读写，不以私有标记开头；尚未连接完整 PC 输入设置和执行状态机。现有文件优先保留，绝不从用户样本复制出所谓官方默认键。
- **移植版兼容模拟映射**：`<角色名>.kbm`，包括旧版 USB HID 转 Switch 控制器输入、鼠标三种角色。支持 `sw_keyboard.txt` 及上版项目标记文本 `.key` 只读迁移；只有用户更改绑定后才写新 `.kbm`。
- **原生手柄**：`<角色名>.ctl` 继续由原生游戏管理，未改二进制内容。
- **事务保存**：私有 `.kbm` 会同步到事务工作目录；若已提交存档中存在 `.key` 且事务目录缺失，则无覆盖地复制进去，避免游戏保存目录替换导致原生文件丢失；事务目录里若已有 `.key` 则优先保留它。无法保证多设备并发修改的逐字段合并。

### 迁移验收

测试覆盖：私有旧 `.key` 只读迁移到 `.kbm`、原版 `.key` 字节不改、私有 `.kbm` 主动配置重新加载、事务提交时原版 `.key` 缺失时恢复和已有工作区修改时不覆盖。原版二进制 `.key` 仍需多个真实样本、官方动作 ID、真正角色切换及原版游戏实际行为测试。

### iCloud 按角色同步的已知限制
目前 `dm_cloudsync.c` 把角色文件夹作为一个整体处理，同名角色在多设备出现并发编辑时，冲突解决按角色包（含 .d2s/.key/.ctl）而非逐字段键位合并。两个设备离线独立改键时，较早或较新的整份角色包可能覆盖另一个设备的键位。该问题属于跨设备一致性限制，不能用本地文件名相同来证明已解决。


## 2026-11-06 源码复核后的补丁与仍存在的差距

本节基于 PR #2 的实际文件和回归条件，不按 commit 标题判定实现。上述表格中写的「待测试」仍意味着未通过真机验收。

- **世界目标**：`dm_world.c:w_hit/w_hover_step` 对 NPC、敌人、交互物件、已有掉落物标签进行命中判定；无名称的 NPC/怪物仍画真实位置描边；使用数据表的本地化键或游戏原生 MonsterHealth/SetInfo 的已渲染名字，不能编造不存在的名称。怪物层级与免疫依据对象属性；不保证所有特殊随机词缀都能在距离之外显示，物件当前只有轮廓、无完整本地化名称。
- **物品信息**：`dm_cursor.c:dm_ui_mouse_hover_now` 根据实体指针重新计算原生焦点，Mac 与移动端持续重试最近一次光标位置；`hand_guard` 对实体鼠标持物跳过触屏闲置归位。原版装备槽、背包、仓库、魔盒仍需跨项目实测，不能只凭当前静态测试认定持物和非法落位安全。
- **鼠标攻击**：`dm_world.c:g_mouse_lock` 在按下时锁住原敌对怪物 ID+类别，重复攻击使用 ID 而非当前指针命中结果；Mac 和移动端仅空地移动才更新光标位置，失效目标禁止改为走路。松键、暂停、面板关闭、退出时清理状态。新增跨设置编辑区的按键归属保持，防止从游戏拖向设置界面后丢失 mouse-up。
- **按键设置实际焦点**：`front_mac.m` 放行原生控件鼠标与滚轮；`DmActivity.java` 区分编辑器与世界的 press ownership；`front_ios.m` 由 UIKit 子视图响应设置项，所有三端编辑键位时抑制游戏快捷键，避免设置过程中意外施法。
- **角色配置失败反馈**：`dm_kbmap_restore_defaults_checked` 复位失败时恢复内存旧值；Mac/iOS/Android 各自提示无法写入角色私有 .kbm；遇到其他格式的原生 .key 时不会静默覆盖。原生 .ctl 仍由游戏管理。
- **仍未实现**：原生 Key1 / Key2 内部结构的替换；鼠标左右中三键配置为任意技能和完整 PC 原生鼠标技能输入；对象真实名字/全部怪物随机词缀；真实游戏构建及三端设备上 5 项功能的端到端验收。
- **验收设备和用例**：iPadOS USB/蓝牙鼠标与键盘；Android USB/蓝牙鼠标与键盘；Mac AppKit 鼠标；必须在正常/全屏、装备栏/仓库/魔盒、单击与拖动、镜头移动与切换区域、存档重启和切角色中逐项复测。特别测试按住怪物拖到设置面板边缘再松手、设置列表滚轮、改键失败及键盘导航不会施法。

CI 通过只证明这些脚本和语法检查在指定模拟环境成功，**没有 PC 二进制文件兼容保证，也没有真机行为通过结论**。
