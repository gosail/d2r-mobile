## 当前机制和证据

- 世界悬停：`dm/host/dm_world.c` 发布 `dm_world_hover_view`，Mac/iOS/Android 分别在出图层上方只读显示。
- 背包光标：`dm_ui_mouse_hover_now` 用原版焦点刷新，鼠标持有物品时不使用触屏的闲置收纳。
- 连续攻击：`g_mouse_lock` 以怪物 ID 和类型为锚点；不合成键鼠目标以外的手柄目标。
- 控制页：目前仅恢复原版 `KeyBindingMenu`，以及与“自定义”页并列的正确页签顺序。**PC 式完整可编辑键盘与鼠标映射未完成。**
- 存档：`.d2s`、`.ctl`、`.key`、`.keyo`、`.ctlo` 的具体二进制兼容性尚未验证；不能将 Switch `.ctl` 或自定义 sidecar 直接宣称可被 PC 读懂。

## 额外验收原则

1. 每个场景在三种平台各自进行鼠标事件录屏与游戏日志比对。
2. 同时回归手指单击、长按拖动、手柄技能绑定和切换 UI 的原逻辑。
3. 无玩家实际 PC `.key` / `.ctl` 文件与原版行为基准时，二进制兼容不可标记通过。
4. 静态 CI 只是代码约束，缺少用户资源时无法执行完整编译或游戏帧回放。

## 键鼠配置（2026-11-06 调整）

**取消 PC .key/.ctl 兼容要求。** 新增 `dm/host/dm_kbmap.c` 本地配置 `sw_keyboard.txt`，存于存档根目录同级，格式为 `D2RMobileKeyboard=1` 文件头加 `USB-HID-usage=action` 覆盖项。保存用临时文件 + 原子改名，不覆盖角色存档、原生手柄绑定表或 PC 文件。

- **Mac 默认基线**：WASD = 左摇杆；J/K/U/I = A/B/X/Y；Q/E/Z/C = L/R/ZL/ZR；F/G = 摇杆点击；方向键 = 十字键；Space = A。移动端加 F1–F8 原生技能位、1–4 药水十字方向、M 地图。
- **iOS**：`DmMetalView pressesBegan/Ended/Cancelled` 通过 `UIKey.keyCode`（USB HID 码）交给配置层；失活清除按下状态。控制页提供「键鼠设置」按键并可编辑、保存。
- **Android**：`KeyboardInput.java` 把 `KeyEvent` 转同一 USB HID 码，由 JNI 交给独立键盘通道；控制页「键鼠设置」弹出编辑器，保存同格式；切后台或失焦清除按下状态。
- **手柄**：继续使用原有 `KeyBindingMenu` 和 `dm_pad_set`，与 `dm_kb_set` 分离；触屏保留 `dm_input_set`。
- **自动测试**：Linux 原生 C 对照覆盖默认键位、组合按键、松键、移动、F5 技能、M 地图以及重启读盘；静态检查三端入口，Apple Objective-C 语法检查，Android 键盘 UI 类 SDK Java 语法检查。
- **待实机验证**：iPad 键盘能否稳定成为 first responder、Android 键盘系统截获、原游戏按键消费、控制页事件可见性、技能与药水实际效果、配置文件在各平台重启后是否正确载入；iOS/Android 的鼠标左、中、右键已可重映射为「主点击 / 次要使用 / 切地图」三种角色（不是无限制任意动作），还需设备事件验证；Mac 的物理鼠标仍采用现有默认功能。

## 2026-11-06 角色文件名规则与冲突保护

实际文件结构是 `$DM_SAVE/<角色名>/<角色名>.d2s`。

- **键鼠**：`$DM_SAVE/<角色名>/<角色名>.key`。文件首行 `D2RMobileKeyboard=1`，内容是平台共用的 USB HID 按键动作映射和 `mouse0..2` 三键角色映射，**不保证兼容 PC 的二进制 .key**。
- **手柄**：`$DM_SAVE/<角色名>/<角色名>.ctl` 继续由原生游戏 `KeyBindingMenu` 管理，宿主不会打开它写键鼠内容，避免破坏游戏的手柄绑定。
- 选角界面确认角色、进游戏时识别到客户端玩家，都会更新当前角色身份；加载新角色的 .key，不把 Alice 的按键覆盖到 Bob。
- 若目标 `.key` 已存在但文件头不属于此项目：**拒绝覆盖**并报告配置保存失败，保留原文件内容。用户需手动迁移/备份该文件，不能自动误删。
- 键鼠设置直接原子写入已提交存档与事务工作目录；游戏保存前还从已提交存档恢复这份键鼠配置到工作目录，降低游戏的原子交换造成改键回退的风险。CI 必须验证工作目录模拟保存与本地既有 `.ctl` 字节不变。
- **限制**：Mac、iOS、Android 各设备的角色目录要通过用户的存档同步流程共享，才能读到同一份 .key；文件名相同不会自动实现跨设备同步。

### 旧版全局配置迁移
若角色的 `<角色>.key` 尚不存在，程序仅**只读**尝试上一版 `sw_keyboard.txt` 作为初始映射；首次按此角色改键后，创建角色专属 `.key`。全局配置文件不删除、不覆盖，其他角色可独立设置。若角色已存在不属于本项目格式的 `.key`，**不会回退读取旧全局文件并覆盖该角色文件**。

事务提交中的工作目录若出现未知格式的同名 `.key`，不主动覆盖。该冲突需要在游戏存档模拟/真实设备上验证，不能把两种不同格式同时写进一个名字。
