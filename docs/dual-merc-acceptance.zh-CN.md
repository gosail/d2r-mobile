# 双佣兵离线功能：可验收条件与实验限制

> 本文件描述目标行为与尚未完成的验收条件。**当前 PR #5 不代表完整双佣兵功能，未通过实机验收；不可用于珍贵角色档。**

## 目标交互

| 当前佣兵 | NPC 候选 | 期望动作 | 是否弹出选择旧佣兵 |
|---|---|---|---|
| 0 名 | 任意有效幕（I/II/III/V） | 直接雇佣，成为位置 1 | 否 |
| 1 名（第一幕） | 第二幕 | 增加第二名，两人同时存活、跟随和战斗 | 否 |
| 1 名（第二幕） | 第二幕，任意难度 | 正常确认替换第二幕佣兵 | 否 |
| 2 名（第一幕+第二幕） | 第三幕 | 先选择替换第一幕或第二幕，再确认 | **是** |
| 2 名（第一幕+第二幕） | 第二幕，任意难度 | 只能替换已有第二幕；原第一幕必须保留 | 否 |
| 2 名（第一幕+第二幕） | 第一幕，任意难度 | 只能替换已有第一幕；原第二幕必须保留 | 否 |
| 2 名且其中一名死亡 | 任意候选 | 死亡佣兵仍占用幕名额和位置 | 根据上面两条规则 |
| 2 名且一个来自第五幕 | 第五幕，任意难度 | 同幕只替换原第五幕；不可出现两个第五幕佣兵 | 否 |

第四幕没有可招募的独立佣兵类型，NPC 复活入口不能算新招募幕。

## 每次事务必须同时通过的验收

1. **雇佣业务**：扣金币或完成确认前就确定位置；取消任何选择必须无副作用；替换失败必须回滚。
2. **服务器队伍**：宠物类型 7 的链表中活跃数量不超过 2，来源幕不得重复；原来的第一名绝不可被新候选无意解除关联或销毁。
3. **客户端显示**：玩家和两个佣兵共同移动、攻击、跨区、回城、切换地图、重进游戏；死亡或复活状态和角色一致。
4. **装备管理**：两套独立面板或一个面板的显式佣兵选择；每件物品只有一个有效持有者。佩戴、卸下、拖动、复制/售卖防护，以及带孔装备与符文必须对两个佣兵一致。
5. **读档**：每名佣兵身份、等级、经验、名字、技能、装备、死亡状态均可完整恢复；原版 .d2s 所属佣兵位置必须和 .swmerc 标记一致。
6. **原子性**：角色 .d2s、扩展 .swmerc 与任何相关仓库旁路文件一次性提交；出现损坏或旧版本要拒绝加载扩展状态，不能复制物品或清空合法角色资料。
7. **兼容性**：线上模式和普通版完全不启用这套修改；不得修改 Bundle ID；升级前有可独立恢复的存档备份。

## 目前已实现（源代码）

- 纯 C 位置策略以及不同难度下同幕唯一性（`dm_dualmerc_policy.h`）
- `SWM2` v2 两名佣兵的身份及各自最多十件装备位流的**未接线**编解码器（`dm_dualmerc_state.h`）
- 具备临时文件、写盘刷盘、原子改名及损坏拒绝的 `.swmerc` **未接线**磁盘模块（`dm_dualmerc_disk.h`）
- 原生 0x687648 查询 hook：仅实验包、旧佣兵及新候选都无装备、来源幕不同，尝试保留第一名；已满两名及装备状态未验证时，阻止原版雇佣命令自动替换（`diag.c`）
- 仅当原生绑定后服务器链表同时包含旧/新两个准确的佣兵 ID 才显示试验提示；仍不声称客户端 UI 和存档已完成

## 目前未实现

NPC 双位置替换选择器、两套可切换装备面板、完整佣兵第二位置的原生保存和载入/重建、经验死亡与复活并行、地图切换和退出重进的全场景验证。原版 NPC “新雇佣将替换旧佣兵”对话也尚未做条件适配。

## 一次性实验操作（仅专用测试 IPA）

1. 用无价值、独立备份的离线角色进入游戏；不要给佣兵任何装备。
2. 雇佣一个第一幕佣兵，确认能正常跟随和战斗。
3. 去第二幕，雇佣一个不带装备的第二幕佣兵。确认两人同时出现在实际场景，不能仅凭数据表上限或 NPC 文案判断。
4. 检查游戏提示是否实际检测到宠物节点数量 = 2。如果没有出现，保留控制台日志：`DM_DUAL_MERC_TRIAL`、`DM_DUAL_MERC_NATIVE`、`DM_DUAL_MERC_PROBE`。
5. **不要在这个尚未具备第二佣兵读档的实验版中给第二名佣兵装备，也不要将成功进入双佣兵状态当成存档可恢复的证明。**

当前离线实验 IPA 使用 `DM_DUAL_MERC_KEEP_FIRST=0` 可关闭临时保留；普通版不存在 0x94 游戏代码 hook，不受这个实验逻辑影响。

## 2026-11-18 回归保护

存档状态机对需要替换的旧佣兵，如仍持有任何装备，即使候选位置正确也拒绝直接覆盖旧记录；必须先在原生游戏界面卸下并由引擎完成装备移交。单元测试还检查装备身份重复、损坏/校验失败、同幕跨难度限制，以及不同难度的死亡佣兵仍占位置。

原生保留实验已修复 UNIT 指针与宠物链表 NODE 指针误比的问题。新版在 `0x6c1b00` 返回之后还必须检查两名准确的原生 ID；验证不到两名则不显示成功提示。**此时不具备通过后恢复旧佣兵的能力**，因此不能在重要存档中进行实验。
